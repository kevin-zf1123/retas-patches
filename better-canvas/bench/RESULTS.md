# Stylos 主画布导航实测

管理器 0.1.3 的键盘连转、倾斜画布缩放及停手延迟另有[输入积压专项实测](INPUT.md)。下文记录首轮原型。

2026-11-27，在 i5-10400、Intel UHD 630、64 位 Windows 上测试了 Stylos 2.6.0 x86 和 CSP EX 3.0.0。首轮原型采用 CPU 快速预览。6144×4096 线稿的双线性旋转中，UI 线程每次输入的 CPU 时间从 32.23 ms 降至 15.62 ms。主要收益来自省去重复插值和跳过已经排队的中间角度。

## Stylos 的时间花在哪里

同一测试构建按关、开、开、关的顺序测试快速导航。每个设置、每种手势共投递 128 次输入，输入间隔约 16 ms，允许应用积压或合并。以下是 6144×4096 单层、120% 起始倍率、双线性的结果，时间单位为 ms。

| 操作 | 快速导航 | 可对应到输入的重绘 | 帧间隔 P50 / P95 | 输入至重绘结束 P50 / P95 | 停手至高清重绘结束 P50 / P95 |
|---|---|---:|---:|---:|---:|
| 旋转 | 关 | 128 | 33.0 / 53.4 | 165.9 / 395.3 | 随当前重绘完成 |
| 旋转 | 开 | 106 | 19.9 / 32.2 | 25.0 / 40.9 | 101.0 / 136.8 |
| 滚轮往返 | 关 | 38 | 31.7 / 177.5 | 12.2 / 37.7 | 随当前重绘完成 |
| 滚轮往返 | 开 | 58 | 25.1 / 93.2 | 11.3 / 28.4 | 114.5 / 123.0 |

旋转基线中，每次输入的像素插值、原生变换绘制、取源区域、纯色扫描分别占 **13.06、4.30、1.51、0.43 ms**。四项之外还有约 12.9 ms 的 UI 线程 CPU，包含宿主其他工作与采样开销，当前计时无法继续归因。每次输入累计申请约 3.91 MiB 临时缓冲。11264 次源块访问中有 9152 次在同一重绘中重复了块坐标，坐标重复本身不足以证明这些区域可跨编辑复用。

旋转在输入处理期间同步绘制，处理时间超过投递间隔就会积压。滚轮在设置倍率后还会滚动以保持指针锚点，跟踪显示这两步通常先完成，再集中绘制。在快速预览中，仍按顺序处理每次输入，只有下一条排队事件也能确认为旋转时才暂缓绘制中间角度。视图稳定后用原有滤镜还原，旋转或镜像状态下的缩放保留原生刷新顺序。

**收益随场景变化。** 2048×1536 单层、双线性滚轮的 P95 输入延迟从 34.6 ms 变为 38.8 ms，同时 64 次输入对应的重绘从 13 次增至 23 次。普通 DGA 的双立方滚轮 P95 帧间隔从 70.3 ms 变为 147.2 ms。这是原型默认关闭的原因。[各测试组数据](results.csv)

## CSP 对照

两款软件打开同一张 2048×1536 弧线线稿，画布视口为 **1239×1146**，起始显示倍率为 **59.5%**。外部观察器读取视口同一相对位置的 128×128 像素区域，记录投递到首次可见像素变化的时间。每次读窗有额外成本，且局部区域可能漏掉其他位置的变化。该组按观测到更新后再投递下一次输入，和上面的固定节奏积压实验采用不同测量口径。

| 软件及设置 | 旋转可见延迟 P50 / P95，ms | 缩放可见延迟 P50 / P95，ms |
|---|---:|---:|
| CSP，快速显示关 | 20.0 / 38.8 | 16.0 / 33.7 |
| CSP，快速显示开 | 8.5 / 30.0 | 8.5 / 32.8 |
| Stylos，双线性 | 97.3 / 121.0 | 57.5 / 79.1 |
| Stylos，双线性快速导航 | 37.8 / 58.7 | 33.3 / 45.7 |

CSP 使用旋转工具和缩放工具拖动，Stylos 使用 5° 旋转指令和 5 个百分点的指针中心滚轮。两套手势的角度、倍率轨迹不同。CSP 私有桌面里投递的滚轮消息在两个设置下各 48 次均未采到像素变化，因此表中的 CSP 缩放值仅来自缩放工具。在 CSP 开启快速显示的缩放拖动中，松手后采样区域达到最终像素的中位时间约 23 ms。此实验支持移植“操作中快速显示、停手恢复画质”的行为；CSP 的采样算法、缓存布局和渲染后端仍未知。[CELSYS 首选项手册](https://help.clip-studio.com/en-us/manual_en/720_preferences/Preferences.htm)

## 32 位与 GPU

测试宿主已启用大地址感知。大画布交错实验的最大采样私有内存约 254 MiB，最小采样最大连续空闲地址区约 1792 MiB。进程硬缺页增量和受测缓冲的分配失败次数均为零。这组负载下，应优先处理 UI 线程和像素重采样；更大文档、更长编辑会话可能产生不同结果。[Windows 地址空间限制](https://learn.microsoft.com/en-us/windows/win32/memory/memory-limits-for-windows-releases)

WPR 系统 CPU/GPU 跟踪因权限错误 `0xc5585011` 未能启动。测试改用 UI 线程 CPU 时间、进程硬缺页、虚拟地址区和按 PID 匹配的 GPU engine running-time 计数器。已匹配引擎在大画布交错实验中的累计增量为零；此计数的覆盖范围不含 DWM 独立进程和未暴露的驱动工作。

本轮保留 D3D11 为后续方案。将最后一次窗口呈现交给 GPU 仍会保留上述 CPU 插值成本。若继续验证，应在合成后的源块处建立纹理缓存，比较纯原生帧与跳过原 CPU 变换后的帧，并单独测上传和窗口呈现。当前原型已在 x86 进程内工作，无需更改可执行文件的大地址标志。

## 正确性与复现

- 普通 DGA、2048×1536 和 6144×4096 线稿分别测试双线性和双立方；另测复制三层并登记另一张 DGA 到透光台的场景。每组停稳后的旋转和缩放画面裁区逐像素匹配，共 **14 对**。登记后通过显示、隐藏参考图确认它确实影响画面。测试使用独立副本及私有桌面。
- 在大画布交错实验中，锚点每轴最大误差均为 0.344 个画纸像素，和基线相同。在叠层测试中，旋转后立即按下的首点两次都映射到画纸上的 (781.992, 545.414)。通过全选观察到的边界包围框一致，在活动选区中往返缩放并取消选择后画面复原。模拟鼠标按下没有在检查区域形成可辨认的笔迹，真实数位笔首笔、压力和笔尖到屏幕的延迟仍待硬件验收。
- 使用 Python 3、Pillow、pefile、LIEF 和 Zig 0.13.0。在仓库根目录运行以下 PowerShell 命令。把应用路径、临时目录和 Zig 路径替换为本机值。测试时先退出同一产品的其他实例。实验用 DLL 只进入新建的测试目录。

```powershell
python better-canvas/bench/prepare.py $installedStylos $lab --zig $zig
python better-canvas/bench/navigation.py $lab "$lab/large.bmp" 1 "$lab/baseline.json.gz" --resources
python better-canvas/bench/navigation.py $lab "$lab/large.bmp" 1 "$lab/fast.json.gz" --resources --fast
python better-canvas/bench/summarize.py "$lab/baseline.json.gz" "$lab/fast.json.gz"
python better-canvas/bench/matched.py $lab "$lab/matched.json.gz" --fast
python better-canvas/bench/csp.py $lab $cspExecutable "$lab/csp.json.gz"
```

模式 0、1、2 分别对应原生、双线性、双立方。对于有权测试的两张本地 DGA，复制到测试目录后使用 `--duplicate-layers 3 --reference <第二张画纸路径> --validate`。CSP 驱动器使用本次日文 3.0.0 和 150% DPI 工作区布局校验菜单和复选框。内部跟踪记录的是 Windows 重绘完成时间，外部跟踪记录窗口表面像素变化；两者均不含显示器扫描输出。CSV 中空值表示该条件没有对应采样。

# 旋转和缩放的输入积压

2026-11-27，Stylos 2.6.0 x86，i5-10400、Intel UHD 630。对比管理器 0.1.2 和 0.1.3，均开启快速导航与双线性插值。测试文件是 `prepare.py` 生成的 6144×4096 弧线线稿，初始倍率为 120%。

## 停手后的延迟

在独立桌面的真实画布上，每个旋转步都投递一对按下和松开消息。每次连续输入 24 步，再等待画面稳定。滚轮每格 5 个百分点。按旧、新、新、旧的顺序重新启动应用，每个版本、每个条件共 12 轮。表中时间均为中位数，单位为毫秒。

| 操作 | 每秒输入步数 | 角度或倍率到位，旧 → 新 | 采样区域像素稳定，旧 → 新 |
|---|---:|---:|---:|
| 旋转 | 30 | 29.4 → 30.3 | 127.1 → 132.0 |
| 旋转 | 120 | 557.5 → 40.9 | 635.3 → 146.6 |
| 滚轮缩放 | 30 | 2.7 → 8.1 | 364.1 → 146.5 |
| 滚轮缩放 | 120 | 1.9 → 7.0 | 364.1 → 130.3 |
| 在 25° 画布上滚轮缩放 | 30 | 66.6 → 11.9 | 157.8 → 171.4 |
| 在 25° 画布上滚轮缩放 | 120 | 28.0 → 7.3 | 111.2 → 163.3 |

角度和倍率取自原生工具栏。像素取自窗口表面的 192×192 区域，计时从最后一条消息投递完毕开始，包含最终插值的变化。没有测量物理设备到显示器的整链路。在较低频率下，旋转到位时间的中位数基本持平；在倾斜画布上，快速预览先抵达目标倍率，线条恢复最终画质会再花一些时间。

另测 120 步/秒、每轮 60 步的连续旋转，正反方向各两轮。按键期间，观察区域每秒可辨认出约 28 次（旧版）和 25 次（新版）像素变化。停手后角度到位的中位延迟约从 1498 ms 降到 44 ms。改善来自每次重绘更接近最新输入，单帧实际绘制仍需占用 UI 线程。

## 实现与核对

- 主消息循环保留原有的按下、松开与快捷键匹配顺序。队列中已有后续导航事件时，先累计目标角度或倍率，再交给宿主绘制。队列变空前提交最后一步；切换画布、移动缩放锚点、滚轮反向或处理其他操作时先提交前序变换。没有等待未来输入的固定时间窗。
- 旋转读取按下消息携带的重复次数。一条重复计数为 3 的右转消息实测得到 15°，旧版为 5°。
- 快速预览在空闲约 60 ms 后请求最终画质。原生刷新会根据画布中心重新计算滚动位置，插件将同一画纸点重新投影回窗口并补偿偏差。已对 0°、5°、45°、45° 加水平翻转四种状态的两个缩放锚点核对 20 个停稳画面，与 0.1.2 逐像素匹配。
- 双线性滤镜使用专用的四像素插值分支，保留原有定点精度和舍入。对随机 RGBA 像素、夹取边界和亚像素坐标做了 90,270 次采样比对，双线性和双立方的四个通道均与原公式一致。

复测时使用安装了旋转快捷键和指针中心滚轮的测试副本，并启用快速导航。按前一份报告配置好独立目录后，可运行以下命令。真实 TourBox 固件、设备映射和物理键盘扫描不在该模拟输入测试中。[测试环境配置](RESULTS.md)

```powershell
python better-canvas/bench/input_tail.py $lab "$lab/large.bmp" "$lab/input-tail.json"
python better-canvas/bench/input_tail.py $lab "$lab/large.bmp" "$lab/checks.json" --kinds key --rates 120 --check-boundaries
```
